1. How your files are protected

Every change the AI makes goes through the same safety nets — no change is ever unrecoverable:

What the AI doesWhat the bridge does firstHow you undo it
Overwrite / edit a fileCopies the current version to the version history (a “snapshot”)Restore an older version
Delete a fileMoves it to the trash — nothing is erasedFind a deleted file
Restore an old versionSnapshots the current version first (restoring is itself undoable)Same as a restore — pick a newer timestamp
Mass-edit many filesEach file is snapshotted individually + the write-rate brake caps the paceRestore each file

On top of all that, the extension asks you first: deletes, overwrites of existing files, restores and bulk operations pop an Approve / Deny card into the chat page and wait for your click. Creating a brand-new file never asks (nothing is at risk).

The one-liner to remember: in chat, just say —

“Show me the previous versions of <file> and restore the one from before the AI's edit.”

2. Restore an older version of a file

Every overwrite keeps the previous content. Easiest way back — ask in chat:

Show me the saved versions of reports/summary.docx

The assistant lists them (newest first), e.g.

20260906-143205-a1b2   reports/summary.docx   14 KB
20260906-091511-c3d4   reports/summary.docx   11 KB

To look at an old version without changing anything:

Show me the content of version 20260906-091511-c3d4

When you've picked, restoring replaces the live file — you'll get one approval card (Restore previous version) to click:

Restore 20260906-091511-c3d4 of reports/summary.docx

That's it. The current content is snapshotted on the way in, so even the restore can be undone the same way.

No chat needed — do it in Finder / Explorer

Unlike the desktop app, the extension keeps snapshots inside your shared folder, in a hidden .ofb-snapshots/ directory (the AI can't see it, but you can):

<your shared folder>/.ofb-snapshots/20260906-143205-a1b2/reports/summary.docx

Open the timestamp folder from before the bad edit and copy the file back yourself — that bypasses the chat entirely.

3. Find a deleted file (trash)

“Delete” never erases — the file moves to .ofb-trash/ inside your shared folder (hidden from the AI; entries auto-expire after 30 days). In chat:

What's in the trash? I'm looking for a file I deleted yesterday.

then

Restore the trash entry 20260905-180033-77aa of notes/old-draft.md

Or fish it out yourself from <your shared folder>/.ofb-trash/<timestamp>/.

Two small rules:

• Trash-restore refuses if a file with that name already exists again — it will never itself overwrite something.

• The trash catches AI/chat deletions. If you delete a file in Finder / Explorer, that's outside the bridge — use your OS trash.

4. “The AI messed up my file!” — walkthrough

  1. Don't panic-edit the file — the old content is already safe in the version history (it was snapshotted before the AI's write).
  2. In chat: “Show me the saved versions of reports/summary.docx.”
  3. Peek at a candidate: “Show me the content of the second one.” (reading an old version never touches the live file).
  4. “Restore that one.” → click Approve on the restore card. The messed-up version is snapshotted on the way in, so you can change your mind.

5. “I regret the whole edit” — many files

When a task touched many files, each one still has its own snapshot. In chat:

The last task rewrote several files. For each of:
  contracts/acme.md, contracts/beta.md, reports/q3.docx
list the versions and restore each to the version from before today's task.

Each restore asks for approval, so a 20-file batch means 20 quick clicks — deliberate friction. For very large batches, your own folder backup is still the gold standard; the version history is a safety net, not a backup product.

6. The write-rate brake (why writes suddenly stop)

If the AI starts writing unusually fast (typically a stuck loop), the bridge refuses further writes for up to a minute instead of hammering your folder. You'll see an error in chat like:

write-rate circuit breaker: 21 writes / 130 KiB in the last 60 s (limits 20 / 50 MiB). STOP and ask the user to confirm the mass edit before continuing.

What to do: nothing is broken and nothing was half-written.

  • reply in chat to confirm you want the mass edit and let it continue, or
  • tell the AI to stop and review what was written (each write is snapshotted anyway), or
  • raise the limits in the extension's settings page → 🛟 Safety & recovery card.

7. Safety settings

Click the Open File Bridge toolbar icon (it opens the settings page):

  • 🛟 Safety & recovery — writes/minute and MiB/minute brake limits (defaults 20 / 50), and Read-only mode: a master switch that blocks every write when you want the AI to analyze but never modify.
  • 🛟 Safety & recovery → approval scope — which operations pop the Approve card: everything (default), only destructive ones (deletes), or none.
  • 📁 Shared folders → Disable writes — a per-folder write block (the AI can read that folder but never change it).
  • 🚫 Ignore patterns — files matching these are invisible to the AI and writes to them are refused.

8. Where snapshots & trash live, and their limits

  • Location — inside each shared folder, in hidden directories the AI can never see or read: .ofb-snapshots/, .ofb-trash/ and .ofb-chunks/ (in-flight large writes). You can browse them in Finder / Explorer at any time.
  • Per-file cap — files over 8 MB are not snapshotted (the write still happens; the response says skipped: "too_large").
  • Retention — trash entries are removed automatically after 30 days (the check runs about once a day while you use the assistant). Snapshots in .ofb-snapshots/ are kept until you delete them — they are the undo history, so nothing prunes them automatically; to reclaim space, empty that folder yourself (the AI can't — it's invisible to it, by design).
  • Survives restarts — the stores are plain folders on your disk; they outlive the browser and extension updates.

9. Extension troubleshooting

“permission needed” error

The browser requires you to re-confirm folder access after the extension was reloaded/updated or when a grant expires.

  1. Click the Open File Bridge toolbar icon (it opens the settings page).
  2. Press Reconnect on the folder — the folder is NOT re-picked.
  3. On the browser's permission bubble choose “Allow on every visit” — that choice is persistent (no ask after future restarts). With it, full browser restarts need no reconnect at all.

“engine_needed” error

PDF text extraction, PDF operations and OCR run inside the extension itself — not on any server. The engines normally start automatically and invisibly the first time the assistant uses them; you should never need to do anything. If a 409 engine_needed error persists anyway: click the toolbar icon, check Auto-start the engines when needed (OCR card) is ticked, then press Open engine tab (manual fallback) and keep that tab open.

“no shared folder configured”

  1. Click the toolbar icon (it opens the settings page).
  2. Choose a folder with Choose folder… — files outside that folder are never accessible.

Writes refused (403)

The folder may be read-only, writes were disabled for it, or global Read-only mode is on — all visible in the settings page.

Legacy formats (.doc, .xls)

Open the file in your office app (Word / Excel / LibreOffice) and save it as .docx / .xlsx — then the assistant can read and edit it.

10. FAQ

The AI overwrote a 20 MB file — where's my snapshot?

Above the 8 MB per-file cap the write succeeds but is not snapshotted. Keep large files out of the shared folder or rely on your own backup for them.

Can the AI restore versions by itself?

Only when you ask — and each restore shows you an approval card first, so it can't swap file versions without a click from you.

Is the version history a backup?

No. It lives in the same folder, is capped (8 MB/file), and prunes nothing automatically. It's an undo net for AI edits — pair it with a real backup for irreplaceable data.

When does the trash empty itself?

Entries older than 30 days are swept automatically about once a day (whenever the assistant is active). Snapshots are never auto-deleted — they hold your undo history.

Do the snapshots survive a browser restart?

Yes — they're plain folders on disk inside your shared folder.

Who can reach my files?

Only the Open WebUI page in your browser, through the extension's narrow pipe, within folders you granted — and every browser permission prompt was yours. No server, no network egress, no token to leak.
