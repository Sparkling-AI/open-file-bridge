Open File Bridge ●

checking whether the extension is running…

This extension lets Open WebUI in your browser read & write files in folders you choose on this computer — no server, no network. The folder grant lives in this browser and is re-checked before every operation.

📁 Shared folders

Only these folders are exposed — nothing else on this computer. After a browser restart the assistant may report permission-needed — press Reconnect (the folder is not re-picked).

🔒 Security

Extension mode replaces the app's origin lock and token with the browser's own permission gate: every read and write is re-checked against the folder grant stored in this browser, and only the Open WebUI page's own code-interpreter sandbox can reach the bridge — nothing else can send requests.

Always on, not configurable: credential-looking files (.env, id_rsa, *.pem, …) are refused; every overwrite keeps the previous version; deletes go to a 30-day trash.

Destructive requests pop up an Approve/Deny card inside the chat page — the assistant retries automatically after you click Approve (single-use, 5 min). Every overwrite still keeps the previous version; deletes go to the 30-day trash.

🚫 Ignore patterns

Files matching these patterns are invisible to the AI — not listed, not readable, and writes to them are refused. One pattern per line, gitignore-style: *.zip, secrets/ (that folder, anywhere), /build (top level only); bare names match at any depth. The preview below updates within seconds of saving.

Always ignored (built in, not editable): .DS_Store · ._* · Thumbs.db · desktop.ini · .ofb-snapshots/ · .ofb-trash/ · .ofb-chunks/

⏳ Link lifetime

How long the chat-answer file links keep working after the assistant posts them. The clock starts when the link is created; a longer lifetime means old chat answers stay clickable for longer.
